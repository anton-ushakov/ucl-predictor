# API бэкенда

Адрес при запуске у вас: `http://localhost:8081` (порт задаётся в `application.properties`).
Тела запросов и ответов: JSON. В Postman: Body → raw → JSON.
Все запросы, кроме регистрации и входа, требуют токен: Authorization → Bearer Token.
Ошибки приходят в виде `{ "status": 409, "message": "понятный текст" }`.

Тур = неделя с понедельника по воскресенье (по московскому времени). Тур обозначается датой
понедельника, например `2026-11-02`.

---------------------------------------------------------------------------------------------

## 1. Вход

| Запрос | Что делает |
|---|---|
| `GET /api/config` | Как устроен вход на этом сервере (без авторизации) |
| `POST /api/auth/simple/register` `{ "username": "ivan" }` | Простой режим: первый вход, придумываем имя |
| `POST /api/auth/simple/login` `{ "username": "ivan" }` | Простой режим: вход на другом телефоне |
| `GET /api/me` | Кто я |
| `POST /api/auth/logout` | Отозвать текущий токен |
| `POST /api/auth/register` `{ "username": "ivan", "password": "secret123" }` | Парольный режим: регистрация |
| `POST /api/auth/login` то же тело | Парольный режим: вход |
| `POST /api/auth/password` `{ "currentPassword": "...", "newPassword": "..." }` | Сменить пароль |
| `POST /api/auth/recover` `{ "username": "ivan", "recoveryCode": "K7M2-QX9P-4RTB", "newPassword": "..." }` | Новый пароль по коду восстановления |
| `POST /api/auth/recovery-code` `{ "password": "..." }` | Новый код восстановления |

### Два режима входа

Сервер работает в одном из двух режимов, настройка `app.auth.mode`:

| Режим | Вход | Вступление в группу |
|---|---|---|
| `SIMPLE` (по умолчанию) | только логин, пароля нет | приглашение от владельца или заявка на вступление |
| `PASSWORD` | логин и пароль, код восстановления | по коду приглашения |

Обе системы есть в коде всегда. Выключенная половина не исчезает, а отвечает ошибкой 409 с
объяснением, что сейчас работает вместо неё. Переключение — одна строка в настройках и перезапуск,
миграций не требуется.

`GET /api/config` отдаёт текущий режим, чтобы приложение показало подходящие экраны:

```json
{ "authMode": "SIMPLE", "passwordsEnabled": false, "requestsEnabled": true,
  "description": "Вход по логину, вступление в группу по приглашению или заявке" }
```

**Простой режим.** При первом входе человек придумывает имя, сервер отдаёт токен, телефон его
запоминает. На другом телефоне достаточно ввести то же имя. Пароля нет вовсе.

Честно о последствиях: кто знает чужой логин, может войти под ним и увидеть чужие прогнозы.
Для компании друзей это обычно приемлемо, но если приложением будут пользоваться посторонние,
переключите `app.auth.mode=PASSWORD`.

## 1.1. Приглашения и заявки (простой режим)

| Запрос | Что делает |
|---|---|
| `GET /api/groups/open` | Группы, в которых я не состою, с состоянием моей заявки |
| `POST /api/groups/{groupId}/join-request` | Подать заявку на вступление |
| `POST /api/groups/{groupId}/invites` `{ "username": "alex" }` | Пригласить участника (только владелец) |
| `GET /api/groups/{groupId}/requests` | Нерешённые заявки и приглашения группы (только владелец) |
| `GET /api/invitations` | Приглашения, адресованные мне |
| `POST /api/requests/{id}/accept` | Принять |
| `POST /api/requests/{id}/decline` | Отклонить |
| `DELETE /api/requests/{id}` | Отозвать своё приглашение или заявку |

Правило простое: **приглашение решает приглашённый, заявку решает владелец группы.** Одновременно
на пару «группа и участник» может быть только одна нерешённая запись. В каждом ответе есть поля
`canDecide` (вам решать) и `canCancel` (вы создали, можете отозвать), а также готовый текст `message`.

### Если пароль забыт### Если пароль забыт

Почты и SMS в приложении нет, поэтому доступ восстанавливается двумя способами.

Этот раздел относится к парольному режиму (`app.auth.mode=PASSWORD`).

**Код восстановления.** При регистрации сервер отдаёт в поле `recoveryCode` код вида `K7M2-QX9P-4RTB`.
Он показывается один раз: в базе хранится только его хеш. С ним через `POST /api/auth/recover` можно
задать новый пароль, не помня старого, даже с нового телефона. После восстановления выдаётся новый код
(старый больше не действует). Регистр, пробелы и дефисы при вводе не важны. После 5 неверных попыток
подряд восстановление блокируется на 15 минут (ответ 429).

**Сброс владельцем группы.** `POST /api/groups/{groupId}/members/{userId}/reset-password` (только
владелец). В ответе временный пароль, который показывается один раз: владелец передаёт его участнику
лично. Все входы участника отзываются, а `mustChangePassword: true` подсказывает приложению сразу
попросить задать свой пароль. Каждый такой сброс записывается в таблицу `password_resets`.

Важно: временный пароль даёт полный вход в учётную запись участника, поэтому сброс доступен только
владельцу группы и только для участника его группы. Сохранённые прогнозы при этом не меняются: изменить
их не может никто, включая владельца.

Смена пароля и восстановление отзывают все входы: остальные телефоны попросят войти заново.

## 2. Группы и настройки

| Запрос | Что делает |
|---|---|
| `POST /api/groups` `{ "name": "Шаурма-лига" }` | Создать группу, вы становитесь её владельцем (OWNER) |
| `POST /api/groups/join` `{ "inviteCode": "K7M2QX9P" }` | Вступить по коду |
| `GET /api/groups` | Мои группы |
| `GET /api/groups/{groupId}` | Участники, настройки и список допустимых вариантов настроек |
| `PUT /api/groups/{groupId}/settings` | Изменить настройки (только владелец) |
| `POST /api/groups/{groupId}/invite-code` | Выпустить новый код приглашения (только владелец) |
| `POST /api/groups/{groupId}/members/{userId}/reset-password` | Сбросить пароль участнику (только владелец), см. раздел 1 |

### Настройки группы

```json
{
  "lockMinutesBefore": 0,
  "tiebreakers": ["EXACT_SCORES", "GOAL_DIFF_HITS"],
  "revealMode": "AFTER_OWN_SUBMIT",
  "submissionMode": "WHOLE_ROUND",
  "countExtraTime": false,
  "countPenalties": false
}
```

**lockMinutesBefore**: за сколько минут до начала матча закрывается приём прогнозов
(0: прогноз можно сохранить до самого начала матча, 60: за час и т. д., максимум 1440).

**tiebreakers**: дополнительные показатели, если у участников поровну баллов. Применяются по порядку
(второй смотрят, только если по первому ничья и т. д.). Пустой список `[]`: без дополнительных
показателей, участники с равными баллами делят место.

| Код | Смысл |
|---|---|
| `EXACT_SCORES` | больше точно угаданных счетов |
| `GOAL_DIFF_HITS` | больше угаданных разниц мячей (прогноз 2:0 при счёте 3:1) |
| `GOAL_ERROR` | меньше суммарная ошибка по голам (не сделанный прогноз = 10 голов ошибки) |
| `EARLIEST_SUBMISSION` | раньше сохранил прогнозы |

**revealMode**: когда видны чужие прогнозы, пока приём прогнозов на матч открыт. **После закрытия приёма
на матч чужие прогнозы видят все участники группы** (в том числе те, кто свой прогноз не сохранил) в любом режиме.

| Код | Смысл |
|---|---|
| `AFTER_OWN_SUBMIT` | пока приём открыт, чужие прогнозы видит тот, кто уже сохранил свой прогноз на этот матч; остальные не видят |
| `AT_LOCK` | пока приём открыт, чужие прогнозы не видит никто; все видят их после закрытия приёма |

Внимание: при `AFTER_OWN_SUBMIT` тот, кто сохраняет позже, может посмотреть прогнозы тех, кто сохранил
раньше. Если важна «честность», выберите `AT_LOCK` (или добавьте `EARLIEST_SUBMISSION`).

**submissionMode**: какими порциями сдаются прогнозы. На честность не влияет: каждый матч всё равно
закрывается в своё время, а чужие прогнозы до этого не видны.

| Код | Смысл |
|---|---|
| `WHOLE_ROUND` | весь тур сразу: нужно заполнить все открытые матчи недели |
| `BY_DAY` | игровой день сдаётся целиком, но дней за раз можно сдать сколько угодно (перенесённый матч — отдельный день) |
| `FREE` | каждый матч можно сохранить отдельно |

**countExtraTime / countPenalties**: какой счёт считать. По умолчанию (`false`, `false`) только основное
время (90 минут). `countExtraTime: true` прибавляет голы добавочного времени (итого 120 минут),
`countPenalties: true` прибавляет голы серии пенальти (например, 1:1 и серия 4:3 даёт 5:4). Флаги
можно включать по отдельности или вместе. Если в матче не было добавочного времени или пенальти, счёт
не меняется.

**Когда настройки вступают в силу.** Как только в группе кто-то сохранил прогноз на тур, правила
этого тура фиксируются и дальнейшие изменения настроек на него не влияют. Новые настройки действуют
на туры, на которые ещё никто не сохранял прогнозы.

**Роли.** Владелец (OWNER) меняет настройки и код приглашения. Прогнозы не может изменить никто, в том
числе владелец: запрет стоит и в коде, и в самой базе данных (триггер).

## 3. Туры и прогнозы

### Список туров

`GET /api/groups/{groupId}/rounds`

Текущая и следующая недели с матчами и недавние прошлые, новые сверху:

```json
[
  { "week": "2026-11-02", "status": "IN_PROGRESS", "matches": 18,
    "predictedByMe": 0, "openForMe": 2, "firstKickoff": "2026-11-03T17:45:00Z" }
]
```

`status`: `UPCOMING` (ничего не началось), `IN_PROGRESS` (идёт), `FINISHED` (итоги подведены),
`NO_PREDICTIONS` (все матчи сыграны, но никто в группе не делал прогнозов, поэтому итоги не подводились).
`openForMe`: на сколько матчей вы ещё можете сделать прогноз.

Прогнозы открыты на текущую и следующую неделю (настройка `app.predictions.weeks-ahead`, по умолчанию 1).

### Экран тура

`GET /api/groups/{groupId}/rounds/2026-11-02`

Матчи тура, ваши прогнозы, чужие прогнозы (по правилам показа), таблица тура. Главное в ответе:

- `canSubmit`, `openMatches`: можно ли сейчас сохранить прогнозы и на сколько матчей.
- `submitWarning`: текст предупреждения для окна подтверждения в приложении.
- `rules`: действующие правила (`frozen: true`, если они уже зафиксированы), включая `countExtraTime`,
  `countPenalties`, словесное описание счёта `scoreDescription`, а также `submissionMode`
  и его описание `submissionDescription`.
- `matches[]`:
  - `open`: на матч можно сделать прогноз; `locked`: приём закрыт; `lockAt`: когда закроется.
  - `predictedCount` из `memberCount`: сколько участников уже сделали прогноз (число видно всегда).
  - `homeScore`/`awayScore`: счёт, по которому считаются баллы в вашей группе (с учётом настроек);
    `scoreDetail`: счёт по частям (`regularHome/Away`, `extraHome/Away`, `penaltiesHome/Away`, null, если
    периода не было).
  - `mine`: ваш прогноз с баллами (баллы появляются, когда матч сыгран).
  - `othersVisible` и `others[]`: чужие прогнозы. Пока приём на матч открыт и вы не сохранили свой
    прогноз: `othersVisible: false`, `others: []`. Когда приём закрыт (`locked: true`), чужие прогнозы видны всем.
  - `counting`: как матч идёт в зачёт: `FULL` (по правилам группы), `REGULAR_ONLY` (только по основному
    времени по решению группы), `EXCLUDED` (не учитывается), `NEEDS_DECISION` и `VOTING` (ждём решения,
    см. раздел 3.1), `NOT_PLAYED`, `CANCELLED`. Пока матч не идёт в зачёт, `homeScore`/`awayScore` пусты.
  - `scoreDecision`: решение по матчу без полных данных (иначе null), см. раздел 3.1.
- `standings`: таблица тура. Пока тур идёт, она предварительная (`standingsFinal: false`),
  после завершения итоговая, с победителями и проигравшими.
- `pendingDecisions`: сколько матчей тура ждут решения; `decisionsForMe`: сколько из них ждут именно вашего
  действия (показывайте в приложении как напоминание).
- `buyers` (проигравшие) и `receivers` (победители): заполняются, когда тур завершён.
- `notParticipated`: участники группы, не сделавшие ни одного прогноза на тур (только для завершённого тура).
  Они в таблицу не попадают и покупать ничего не должны.

### 3.1. Матч без данных о добавочном времени или пенальти

Если в группе включён счёт с добавочным временем и/или пенальти (`countExtraTime`, `countPenalties`), а
football-data.org ещё не отдала эти данные по сыгранному матчу, баллы по правилам группы посчитать нельзя.
Пока данные не поступили, тур не подводится, а в `matches[]` у матча появляется `scoreDecision`:

```json
{ "state": "NEEDS_DECISION", "missing": ["PENALTIES"], "canPropose": true, "canVote": false,
  "myVote": null, "agreed": [], "disagreed": [], "waiting": ["petr"], "message": "..." }
```

Порядок такой:
1. Владелец группы (и только он) решает: `POST /api/groups/{groupId}/matches/{matchId}/score-decision`
   с `{ "countRegularTimeOnly": true }` (предложить посчитать матч только по основному времени) или
   `{ "countRegularTimeOnly": false }` (не согласен: матч не учитывается при подведении итогов, состояние `DECLINED`).
2. После предложения (`VOTING`) все остальные участники тура (те, кто сделал прогнозы на эту неделю) должны выразить
   согласие: `POST /api/groups/{groupId}/matches/{matchId}/score-decision/vote` с `{ "agree": true }`
   или `{ "agree": false }`. Голос окончательный. Согласие владельца это само предложение.
3. Все согласились: `ACCEPTED`, матч считается только по основному времени. Хотя бы один против: `DECLINED`,
   матч не учитывается. Пока кто-то не проголосовал и никто не против, остаётся `VOTING` (до `votingEndsAt`).
   **Срок голосования: сутки с момента предложения.** Если за это время согласились не все, матч не
   учитывается (`DECLINED`). Проверка срока идёт вместе с подведением итогов, то есть раз в 30 минут.
4. Если football-data.org позже пришлёт недостающие данные, решение теряет силу: матч считается по правилам группы.
5. Когда тур подведён, решения по его матчам уже не принимаются (409).

Ответ на оба запроса: обновлённый `scoreDecision` (поле `message` содержит готовый текст для экрана).
Матч, который не учитывается, не даёт баллов и не влияет ни на таблицу тура, ни на показатели.

### Сохранение прогнозов

`POST /api/groups/{groupId}/rounds/2026-11-02/predictions`

```json
{
  "confirmed": true,
  "predictions": [
    { "matchId": 12, "homeGoals": 2, "awayGoals": 1 },
    { "matchId": 13, "homeGoals": 0, "awayGoals": 0 }
  ]
}
```

- В приложении сначала нужно показать окно подтверждения с текстом `submitWarning`; только после
  согласия пользователя отправляется запрос с `"confirmed": true`. Без этого сервер откажет.
- Все прогнозы сохраняются одной операцией (всё или ничего). Сколько матчей нужно указать за раз,
  задаёт `submissionMode` группы: весь тур, игровой день целиком или один матч. Матчи, на которые приём
  уже закрыт или прогноз уже сохранён, указывать не нужно.
- Если пока вы вводили прогнозы, приём на какой-то матч закрылся, ответ 409 с названием матча, и ничего не
  сохраняется. Обновите экран тура и отправьте прогнозы на оставшиеся матчи.
- После сохранения изменить прогноз нельзя. Матч, на который прогноз не сделан, даёт 0 баллов.
- В этот момент сервер ставит время сохранения (его нельзя подделать с телефона) и фиксирует правила тура.

Ответ 201: `{ "saved": 2, "savedAt": "...", "message": "..." }`.

## 4. История и общий зачёт

`GET /api/groups/{groupId}/history`: завершённые туры, новые сверху. В каждом: места, баллы, точные счета,
угаданные исходы, ошибка по голам, применённый счёт (`countExtraTime`, `countPenalties`, `scoreDescription`), победители (`winner`) и проигравшие (`loser`), списки `buyers` и
`receivers` и применённые дополнительные показатели. Итоги записываются один раз и не меняются, даже если
потом поменять настройки группы.

Подробный разбор конкретного тура с прогнозами и баллами по каждому матчу: `GET .../rounds/{неделя}`
(для завершённых туров тоже).

`GET /api/groups/{groupId}/leaderboard`: общий зачёт по всем завершённым турам: сумма баллов, число
точных счетов, число побед и поражений (сколько раз покупал шаурму). При равенстве баллов выше тот, у кого больше
точных счетов, затем больше побед; если и они равны, место делится.

## 4.1. Оповещения

Сервер готовит оповещения сам (вместе с остальной фоновой работой, раз в 30 минут), а телефон их забирает.

| Запрос | Что делает |
|---|---|
| `GET /api/notifications` | Оповещения (новые сверху), число непрочитанных, настройки и список видов |
| `GET /api/notifications?unreadOnly=true` | Только непрочитанные |
| `POST /api/notifications/read` `{ "ids": [12, 13] }` | Отметить прочитанными (пустое тело — все) |
| `GET /api/notifications/settings` | Настройки оповещений |
| `PUT /api/notifications/settings` `{ "lockSoon": true, "matchFinished": true, "summary": false }` | Изменить |

Три вида, каждый включается отдельно и для каждого участника свой:

| Код | Когда приходит |
|---|---|
| `LOCK_SOON` | за час до закрытия приёма прогнозов, и только если прогноз ещё не сохранён |
| `MATCH_FINISHED` | матч сыгран: счёт, ваш прогноз и сколько баллов он принёс |
| `SUMMARY` | итоги игрового дня (ваши баллы за день и кто ведёт в туре) и итоги тура (место, баллы, кто покупает шаурму) |

Если участник ничего не настраивал, включены все три вида. Одно и то же оповещение дважды не
приходит. Чтобы при первом запуске не прислать гору старых, берутся только свежие события: матчи,
начавшиеся за последние сутки, и туры, подведённые за последние сутки. Матч, по которому группа ещё
не решила, как считать счёт (раздел 3.1), оповещения не вызывает до решения.

## 5. Как определяются победитель и проигравший

- Баллы: точный счёт 3, верный исход 1, иначе 0.
- Счёт матча по умолчанию берётся по итогам основного времени (90 минут). В настройках группы можно
  добавить добавочное время и/или пенальти (см. `countExtraTime`, `countPenalties`).
- Матч, по которому нет полных данных, идёт в зачёт по решению группы (раздел 3.1).
- Участвует только тот, кто сохранил хотя бы один прогноз на тур. Кто не сделал ни одного прогноза, в туре
  не участвует: не попадает в таблицу, проигравшим не считается и ничего не должен. Если участник сделал
  прогнозы лишь на часть матчей, за остальные ему начисляется 0 баллов.
- Победитель(и): первое место, проигравший(е): последнее. Если все делят одно место, победителей и
  проигравших нет.
- Итоги тура подводятся автоматически, когда все его матчи сыграны (проверка раз в 30 минут).

## 6. Проверка в Postman (пример)

1. Зарегистрируйте `ivan` и `petr`, сохраните токены. `ivan` создаёт группу, `petr` вступает по коду.
2. `ivan`: `GET /api/groups/1/rounds`: найдите неделю с `openForMe` больше 0.
3. `ivan`: `GET /api/groups/1/rounds/{неделя}`: возьмите `matchId` из блока `matches` где `open: true`.
4. `ivan`: `POST .../predictions` с `confirmed: true` и прогнозами на все открытые матчи.
5. Повторите тот же запрос: ответ 409, прогноз изменить нельзя.
6. `petr`: `GET .../rounds/{неделя}`: у матча `predictedCount: 1`, `othersVisible: false` (вы ещё не сохранили свой прогноз).
7. `petr` сохраняет свои прогнозы, после этого в `others` видны прогнозы `ivan`.
8. Проверка режима `AT_LOCK`: `PUT /api/groups/1/settings` с `"revealMode": "AT_LOCK"` (до первых прогнозов
   в туре или в новом туре), и чужие прогнозы не видны до закрытия приёма.
