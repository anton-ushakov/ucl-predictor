# Размещение на сервере

Инструкция подойдёт любому серверу с Linux: Selectel, Timeweb, Hetzner, Oracle. Весь проект
работает в Docker, поэтому устанавливать Java и PostgreSQL вручную не нужно.

Настройки рассчитаны на скромный сервер: **1 ядро, 2 ГБ памяти, 25 ГБ диска**. Этого хватает
с запасом: база занимает меньше сотни мегабайт даже за годы игры.

## 1. Создать сервер

В панели выбранного хостинга создайте сервер:

- Образ: **Ubuntu 24.04**
- Конфигурация: **1 vCPU, 2 ГБ RAM, 25 ГБ диска**
- Внешний IPv4-адрес: обязательно нужен
- Доступ: по SSH-ключу, если умеете его делать, иначе по паролю

После создания запишите IP-адрес сервера, например `203.0.113.10`.

## 2. Подключиться к серверу

На своём компьютере откройте терминал (в Windows подойдёт PowerShell или терминал в IntelliJ):

```
ssh root@203.0.113.10
```

Подставьте свой адрес. При первом подключении спросит про отпечаток ключа — ответьте `yes`.
Дальше введите пароль из письма, система попросит сразу придумать новый.

## 3. Добавить файл подкачки

Это обязательный шаг на сервере с 2 ГБ: во время первой сборки Maven ненадолго попросит
дополнительную память. Без подкачки сборка оборвётся.

```
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Проверить: команда `free -h` должна показать 2 ГБ в строке Swap.

## 4. Установить Docker

Выполните на сервере одну команду:

```
curl -fsSL https://get.docker.com | sh
```

Проверить, что получилось:

```
docker --version
```

## 5. Загрузить проект на сервер

Самый простой путь — через GitHub (заодно у проекта появится история версий):

```
apt update && apt install -y git
git clone https://github.com/ВАШ_ЛОГИН/ucl-predictor.git
cd ucl-predictor
```

Если репозитория нет, скопируйте папку с компьютера. Команда выполняется **на вашем компьютере**,
а не на сервере:

```
scp -r C:\путь\к\ucl-predictor root@203.0.113.10:/root/
```

Файлы из этого архива (`Dockerfile`, `docker-compose.yml`, `Caddyfile`, `.env.example`,
`.dockerignore`, `backup.sh`) должны лежать в корне проекта, рядом с `pom.xml`.

## 6. Настроить секреты

На сервере, в папке проекта:

```
cp .env.example .env
nano .env
```

Заполните четыре строки: пароль базы (придумайте длинный), токен football-data.org, адрес сервера
и часовой пояс. Сохранить в nano: `Ctrl+O`, `Enter`, затем `Ctrl+X`.

**Про адрес.** Если домена нет, напишите `203.0.113.10.sslip.io`, подставив IP своего сервера.
Это бесплатная служба: такое имя само указывает на ваш адрес, и сертификат HTTPS для него
выдаётся как для обычного домена. Свой домен (около 10 € в год) выглядит приятнее, но не обязателен.

## 7. Открыть порты

```
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
```

Порт базы наружу не открыт: она доступна только приложению внутри Docker.

## 8. Запустить

```
docker compose up -d --build
```

Первая сборка на одном ядре займёт минут десять: скачиваются Maven и зависимости, потом идёт
компиляция. Это бывает только в первый раз, дальше запуск занимает секунд двадцать. Посмотреть, как идут дела:

```
docker compose logs -f app
```

Строка `Started PredictorApplication` означает, что всё поднялось. Выйти из просмотра: `Ctrl+C`.
Flyway сам создаст таблицы и применит все миграции.

Проверить снаружи — откройте в браузере:

```
https://ваш_адрес/api/groups
```

Ответ `{"status":401,...}` — это успех: сервер жив и требует авторизацию.

## 9. Переключить приложение на сервер

В Android Studio откройте `data/ServerConfig.kt` и замените адрес на свой:

```kotlin
const val BASE_URL = "https://ваш_адрес/"
```

Косая черта в конце обязательна. Соберите приложение заново. Теперь кабель и команда
`adb reverse` больше не нужны, а оповещения начнут приходить сами.

## Что делать дальше

**Обновить приложение после моих правок:**

```
cd ucl-predictor
git pull            # или заново скопировать файлы через scp
docker compose up -d --build
```

**Посмотреть, что работает:**

```
docker compose ps
docker compose logs -f app
```

**Перезапустить:**

```
docker compose restart app
```

**Резервная копия базы:**

```
./backup.sh
```

Копии лежат в папке `backups`, хранятся последние 14. Чтобы делать их автоматически каждую ночь
в 4 утра, выполните `crontab -e` и добавьте строку:

```
0 4 * * * cd /root/ucl-predictor && ./backup.sh
```

**Восстановить из копии:**

```
gunzip -c backups/ucl-2026-11-10-0400.sql.gz | docker compose exec -T db psql -U predictor ucl_predictor
```

## Если что-то пошло не так

- **Сертификат не выдаётся.** Проверьте, что порты 80 и 443 открыты и что адрес в `.env`
  действительно указывает на этот сервер. Логи: `docker compose logs caddy`.
- **Приложение не стартует.** Смотрите `docker compose logs app`. Чаще всего это пустая или
  неверная строка в `.env`.
- **Матчи не загружаются.** В логах будет строка про токен football-data.org. Проверьте `.env`
  и перезапустите: `docker compose up -d`.
- **Кончилось место.** `docker system prune -a` удалит старые образы и кэш сборки. На диске в
  25 ГБ это стоит делать изредка, после нескольких обновлений.
- **Сборка оборвалась со словом `Killed`.** Не хватило памяти: проверьте, что файл подкачки
  включён (`free -h`), и повторите.
- **Сколько памяти занято сейчас:** `docker stats --no-stream`. В норме приложение держит
  около 500 МБ, база 150–250 МБ.
